# PR QA Fixes & Local Verification Guide

This PR addresses the QA bugs reported in the **AI Platform module**.

## QA Issues Addressed

### 1. Document Ingestion Stuck in `PENDING`

* Completely removed **Celery** from the document ingestion flow.
* Background processing now uses standard **FastAPI `BackgroundTasks`**.
* Job state is updated natively through a new **`AiJob` database model**.
* Polling endpoints now correctly query the `AiJob` database table.

### 2. Chat RAG Unwired

* Wired the frontend chat button inside a proper form.
* Captures the user's text input and sends a `POST` request to:
  `/api/v1/ai/chat`
* The endpoint now returns a mock RAG JSON response.
* Responses are correctly displayed in the interface chat window.

# Local Verification & Testing Guide

## 1. Build and Start Docker Services

From the project root, rebuild the Docker images without using the cache:

```bash
docker compose build --no-cache
```

Stop any existing containers:

```bash
docker compose down
```

Start the services in detached mode:

```bash
docker compose up -d
```

Verify the database container logs:

```bash
docker compose logs -f db
```

> Keep the logs open temporarily to confirm that the database starts successfully.

---

## 2. Start the Backend

Activate the backend virtual environment and start the FastAPI server:

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000
```

The backend should now be available on:

```text
http://localhost:8000
```

---

## 3. Run Database Migrations

Before testing the AI endpoints, make sure the latest Alembic migrations are applied:

```bash
cd backend
alembic upgrade head
```

This ensures the new `AiJob` model and related database changes are available.

---

## 4. Verify Database Access

Open a PostgreSQL shell inside the database container:

```bash
docker compose exec db psql -U postgres -d businesshub_db
```

Once inside PostgreSQL, you can verify the relevant organization users and roles:

```sql
SELECT u.id, u.email, u.full_name, ur.role
FROM users u
JOIN user_roles ur ON u.id = ur.user_id
WHERE ur.organization_id = '1e2bd16b-7399-4431-95d3-e9c9126374d3';
```

This can be used to confirm that the expected users and roles are present before performing authenticated AI-platform testing.

Exit PostgreSQL with:

```sql
\q
```

---

## 5. Run Backend Tests

Run the AI endpoint test suite:

```bash
cd backend
pytest tests/test_ai_endpoints.py
```

Confirm that the tests pass before moving to frontend verification.

---

## 6. Start the Frontend

From the frontend directory:

```bash
cd frontend
npm start
```

Open the application in the browser and verify the AI Platform flows.

---

## 7. UI Verification

### Document Ingestion

* Upload a document.
* Confirm that the upload creates an ingestion job through the endpoint.
* Verify that the job is persisted using the `AiJob` database model.
* Confirm that the job state progresses correctly instead of remaining stuck in `PENDING`.
* Verify that the polling endpoint returns the current job state from the database.

### Chat RAG

* Enter a message in the chat input.
* Click **Send**.
* Confirm that the frontend sends a `POST` request to:

```text
/api/v1/ai/chat
```

* Verify that the endpoint returns the mock RAG JSON response.
* Confirm that the response is displayed correctly in the chat window.
